How I work

01
Listen first

I ask what the thing actually needs to do and who's going to use it. The goal shapes everything — I don't want to build the wrong thing well.

02

Visual direction, component layout, how the interactions should feel. I sketch it before touching a file.

03
Build it

I write code I'd be happy to read back later. Small pieces, sensible names, nothing clever just for the sake of it.

04
Get it live

Deployed, checked on real devices, and handed over properly. If something's confusing, I document it.
